## Product vision

Create an extensible analysis environment for biological measurements, experiments, and models with transparent provenance and validated methods.

A successful implementation should let a researcher start in the browser, continue on Windows, macOS, or Linux, automate the same work from a CLI or notebook, and move a validated workload to a container or HPC scheduler without changing the scientific definition of the project.

## Core scope

- Experiment, sample, measurement, metadata, and controlled-vocabulary models
- Composable quality control, statistical analysis, and domain method plugins
- Batch and interactive workflows with immutable inputs and environment capture
- Publication-ready tables, figures, and machine-readable exports
- Portable project manifests that record inputs, parameters, software versions, random seeds, and output checksums
- A stable API exposed through typed SDKs, a CLI, and an MCP server so Skills and research agents can call the same validated operations

## Platform contract

- **Web:** responsive browser application and installable PWA; no mandatory cloud account for local projects
- **Desktop:** signed Tauri packages for Windows, macOS, and Linux sharing the web interface
- **Automation:** identical commands on PowerShell, Bash, notebooks, and CI runners
- **Scale-out:** OCI containers, resumable jobs, and adapters for Slurm or Kubernetes where workloads require them
- **Accessibility:** keyboard-complete operation, WCAG 2.2 AA contrast, reduced-motion support, and screen-reader names
- **Internationalization:** UTF-8 projects and an English-first interface with complete Simplified Chinese localization

## Reference architecture

- Rust project, metadata, and provenance core
- Python and R analysis plugins executed in pinned environments
- Browser-first interface with PWA and Tauri desktop packaging
- CLI, notebooks, remote compute, and MCP data connectors
- Content-addressed artifacts and an append-only provenance log separate scientific state from interface state
- Capability permissions isolate filesystem, network, compute, and instrument access for plugins, Skills, and MCP clients
- Versioned schemas and deterministic migrations keep projects readable across releases

## Interoperability

- ISA-Tab
- CSV and Parquet
- HDF5 and Zarr
- OME formats where applicable
- JSON-LD
- RO-Crate-compatible provenance and CITATION.cff metadata for publication and archiving
- JSON Schema or equivalent machine-readable contracts for every public operation
- Importers are read-only by default; exporters include round-trip and loss reports

## Delivery roadmap

### Phase 0 - Evidence and specification (weeks 0-4)

- Interview at least eight researchers who use workflows related to "脂质鉴定软件".
- Collect only redistributable fixtures and document expected scientific results with tolerances.
- Publish the project schema, threat model, licensing policy, and compatibility non-goals.

### Phase 1 - Reproducible vertical slice (weeks 4-20)

- Implement one end-to-end research workflow from import through validated result and export.
- Ship browser/PWA, desktop previews, CLI parity, provenance capture, and deterministic example projects.
- Publish an extension API plus one A3S Skill and one MCP tool group for the vertical slice.

### Phase 2 - Public beta (weeks 20-40)

- Add the remaining core capabilities, batch execution, checkpoints, collaboration, and large-project profiling.
- Complete Windows, macOS, and Linux packaging with signed, reproducible release artifacts.
- Run blinded comparison studies against published reference workflows and record all discrepancies.

### Phase 3 - Stable 1.0 (weeks 40-62)

- Freeze stable project and API contracts; publish migration, backup, and long-term support policies.
- Complete accessibility, privacy, security, performance, and scientific-method audits.
- Deposit reference datasets, method notes, checksums, and release artifacts in a durable archive.

## Verification plan

- **Scientific validity:** Reproduce public datasets, verify file round trips and numerical methods, and require domain-expert review for each analysis module.
- **Cross-platform parity:** run identical fixture projects on current Windows, macOS, and two Linux distributions; compare normalized artifacts and tolerances.
- **Reproducibility:** rebuild every release in CI, rerun examples from a clean machine, and verify declared seeds, environments, and checksums.
- **API stability:** contract-test the UI, CLI, SDK, Skill, and MCP paths against the same operation definitions.
- **Human factors:** observe domain researchers completing representative tasks without developer assistance.

## Risks and non-goals

- Numerical agreement must be defined by domain tolerances and independent reference results, not by copying a proprietary implementation.
- File-format support does not imply compatibility when a format is undocumented; prefer documented standards and publish loss reports.
- Agent automation never bypasses permissions, provenance, validation gates, or researcher approval for consequential actions.
- Version 1.0 is not a promise to reproduce every feature or historical quirk of the catalog entry.
- Cloud services remain optional unless a workflow explicitly requires shared infrastructure or remote compute.
